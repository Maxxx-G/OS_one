# Voice Reasoning Loop Guard — v2025.10.07

## Purpose
Document the behavior, constraints, and audit expectations for the Voice Phase-3 Reasoning Loop feature.

## Overview
The Reasoning Loop (`ReasoningLoop.tsx`) provides a client-side automation that continuously triggers voice input cycles (listen → transcribe → respond → speak) without manual user interaction.

## Hotkey
- **Alt+R**: Toggle reasoning loop on/off
- Works globally when component is mounted
- Visual feedback via pill status (On/Off/Muted)

## Start/Stop Behavior

### Start Conditions
✅ Must pass SEC-COMMS gate check (`os1.seccomms.ack` localStorage key)  
✅ `NEXT_PUBLIC_DIRECT_DISABLED` must not be `true`  
✅ User clicks "Start" button or presses Alt+R  

### Stop Conditions
🛑 User clicks "Stop" button or presses Alt+R again  
🛑 Component unmounts (cleanup)  

### Loop Cycle
1. **Check voice status** from `window.os1Voice.get()`
2. **Wait if busy**: If status is `listening`, `streaming`, `speaking`, or `error`, skip tick
3. **Check TTS muted**: If `window.os1Voice.isTtsEnabled()` returns `false`, show "Muted" and skip
4. **Trigger recording**: Dispatch synthetic `Alt+M` KeyboardEvent to activate STT
5. **Wait 2 seconds** and repeat

## SEC-COMMS Respect

### Direct Mode Gate
- Checks `localStorage.getItem('os1.seccomms.ack') === 'true'`
- If `NEXT_PUBLIC_DIRECT_DISABLED === 'true'`, loop is blocked
- On gate failure, emits audit event: `voice-reasoning-start { blocked: 'sec_gate' }`
- Shows alert: "SEC-COMMS acknowledgment required for reasoning loop"

### Mediated Mode
- Loop respects existing mediated/direct routing
- Does not bypass ChatSequencer's mode enforcement
- All LLM calls route through existing provider logic

## Audit Events

### Lifecycle
- **`voice-reasoning-start`**: Loop activated (includes `{ blocked: 'sec_gate' }` if gated)
- **`voice-reasoning-tick`**: Each loop iteration (includes `{ action: 'trigger_recording' }` or `{ skip: 'tts_muted' }`)
- **`voice-reasoning-stop`**: Loop deactivated
- **`voice-reasoning-error`**: Exception caught (includes `{ error: 'message' }`)

### Audit Sink Integration
All events emit via `window.os1Audit.log(type, data)` and appear in the AuditSink panel (Alt+A).

## Failure Cases

### TTS Muted
- **Symptom**: Pill shows "Muted" status (orange indicator)
- **Cause**: `window.os1Voice.isTtsEnabled()` returns `false`
- **Resolution**: Enable TTS via VoiceControls (Alt+Shift+P)
- **Audit**: `voice-reasoning-tick { skip: 'tts_muted' }`

### Voice Busy
- **Symptom**: Loop pauses, pill shows "Processing"
- **Cause**: Voice status is not `idle` (stuck in `streaming`, `speaking`, etc.)
- **Resolution**: Wait for current voice operation to complete; manual intervention may be needed
- **Audit**: No special event (tick waits)

### SEC-COMMS Unacknowledged
- **Symptom**: Alert shown, loop does not start
- **Cause**: `localStorage.getItem('os1.seccomms.ack') !== 'true'`
- **Resolution**: Acknowledge SEC-COMMS policy via SecCommsPill
- **Audit**: `voice-reasoning-start { blocked: 'sec_gate' }`

### Direct Mode Disabled
- **Symptom**: Loop blocked at startup
- **Cause**: `NEXT_PUBLIC_DIRECT_DISABLED=true` in environment
- **Resolution**: Remove or set to `false` in `.env.local`, restart dev server
- **Audit**: `voice-reasoning-start { blocked: 'sec_gate' }`

## Integration Points

### Existing Components
- **VoiceControls**: Alt+M recording trigger is reused
- **ChatSequencer**: Routes transcripts through existing message flow
- **AuditSink**: Displays all reasoning loop events
- **os1Voice global**: Voice status checked via `getVoiceStatus()`

### No Backend Changes
- Loop is purely client-side orchestration
- Reuses existing `/api/transcribe`, `/api/chat`, `/api/tts` routes
- No new API endpoints required

## UI Placement
- **Position**: Fixed bottom-center, above HUD (z-index: 900)
- **Pill**: White background, gray border, rounded
- **Status Indicator**: 8px circle (green=On, gray=Off, orange=Muted)
- **Button**: Blue, hover/active states

## Testing

### Smoke Test
1. Load app, verify pill renders at bottom-center
2. Press Alt+R → pill shows "Reasoning: On"
3. Verify audit events appear in AuditSink (Alt+A)
4. Press Alt+R again → pill shows "Reasoning: Off"

### Loop Cycle Test
1. Start loop (Alt+R)
2. Speak when recording starts (Alt+M auto-triggered)
3. Wait for TTS response
4. Verify loop repeats after 2 seconds
5. Check audit: `voice-reasoning-start`, multiple `voice-reasoning-tick`, `voice-reasoning-stop`

### SEC-COMMS Gate Test
1. Clear `localStorage.removeItem('os1.seccomms.ack')`
2. Try to start loop (Alt+R)
3. Verify alert shown
4. Check audit: `voice-reasoning-start { blocked: 'sec_gate' }`
