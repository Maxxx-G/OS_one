# Voice Stream Guard Checklist

## Purpose

Verify that the streaming TTS implementation works correctly with the HUD animation and fallback behavior.

## Checklist

- [ ] Toggle `NEXT_PUBLIC_TTS_STREAM=1` in environment variables
- [ ] Send a prompt; observe HUD label "Streaming…" with animated bars while audio plays
- [ ] Disable flag or remove TTS key; HUD falls back to "Muted" or non-streaming behavior
- [ ] Verify Alt+M still works (no regressions in voice recording)
- [ ] Confirm audit entry `voice-online` via `tts-stream` in logs
- [ ] Test with streaming disabled (`NEXT_PUBLIC_TTS_STREAM=0` or unset); verify fallback to non-streaming TTS
- [ ] Check that 412 status still shows "Muted" toast and state
- [ ] Verify streaming animation displays correctly (smooth pulsing bars)
- [ ] Confirm audio playback completes and HUD returns to "Idle" state

## Expected Behavior

### With Streaming Enabled

1. Assistant replies trigger POST to `/v1/audio/tts/stream`
2. HUD shows "Streaming…" label with animated bars (vhs-stream animation)
3. Audio plays via MediaSource API
4. On completion, HUD returns to "Idle"
5. Audit logs show `via: "tts-stream"`

### With Streaming Disabled or Failed

1. Falls back to regular TTS endpoint (`/api/tts`)
2. HUD shows "Speaking…" with standard animation
3. Audio plays via regular Audio element
4. No streaming-specific audit logs

### With TTS Key Missing

1. HUD shows "Muted" state
2. Toast notification: "TTS disabled (no ElevenLabs key)"
3. No audio playback attempted
4. Audit log shows `muted: true`
